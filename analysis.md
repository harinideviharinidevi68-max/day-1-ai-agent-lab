# Day 1 – Comparing a Plain Chatbot, Rule-Based Workflow, and AI Agent

## 1. Scenario

The scenario chosen for this project is a College Course Fee Assistant. The system helps users find course fees and answer questions related to multiple course fees, discounts, and budget-based course selection.

The course data used in this project contains the following example course fees:

- CS101 – ₹12,000
- AI202 – ₹18,000
- DS303 – ₹15,000

The same scenario is implemented using three different approaches: a plain chatbot, a rule-based workflow, and an AI agent.

---

## 2. Plain Chatbot

The plain chatbot uses an LLM to understand the user's question and generate a natural-language response. It does not use external tools or a multi-step tool-calling loop.

For this scenario, the chatbot receives questions related to course fees and produces an answer using the information available to the model. It is useful for simple conversational questions because it can understand natural language and respond flexibly.

However, the plain chatbot has limitations when accurate private course-fee information or calculations are required. Without a dedicated tool or controlled data source, it may not reliably retrieve the correct fee or perform multi-step calculations. Therefore, it is less suitable when the answer depends on exact institutional data.

---

## 3. Rule-Based Workflow

The rule-based workflow follows predefined steps and conditions. It does not use an LLM to decide what action should be taken.

In this project, the workflow checks whether the user's question is related to course fees and follows predefined logic. It can retrieve course-fee information and perform predefined calculations when the required pattern is supported.

The main advantage of this approach is predictability. The same input follows the same predefined rules, making the result easier to test and audit. However, the workflow is less flexible because it can only handle situations that have been explicitly programmed. New or unexpected types of questions may not be handled correctly.

---

## 4. AI Agent

The AI agent combines an LLM, tools, and a loop.

The LLM first understands the user's request and decides whether a tool is required. The agent can call the `get_course_fee` tool to retrieve course-fee information and the `calculator` tool to perform arithmetic. After receiving the tool result, the agent observes the result and decides whether another tool call is necessary. This process continues until a final answer can be produced or the maximum number of steps is reached.

For example, for the question:

"What is the total fee for CS101 and AI202 after a 10% scholarship?"

the agent performs the following steps:

1. Retrieves the fee of CS101.
2. Retrieves the fee of AI202.
3. Uses the calculator to apply the 10% scholarship.
4. Produces the final answer of ₹27,000.

This demonstrates the Agent = LLM + Tools + Loop concept.

The agent is more flexible for multi-step questions because the LLM can decide which available tools are needed. However, it requires more processing and its behaviour can be less predictable than a fixed workflow.

---

## 5. Comparison Table

| Basis for comparison | Plain chatbot | Rule-based workflow | AI agent |
|---|---|---|---|
| Flexibility | High for natural-language conversation | Low because steps are predefined | High because the LLM can select actions |
| Decision-making | LLM generates the response | Predefined conditions decide the path | LLM decides which tools and steps are needed |
| Tool usage | No dedicated tools | Uses predefined program logic | Uses tools such as fee lookup and calculator |
| Private-data access | Limited unless private data is explicitly provided or connected | Can access predefined application data | Can access private data through available tools |
| Multi-step task handling | Limited | Possible only if explicitly programmed | Supports multi-step tool usage |
| Automation | Basic response generation | High for fixed tasks | High for dynamic multi-step tasks |
| Reliability | Can vary because responses are generated by an LLM | Predictable for predefined cases | Depends on both the LLM and tools |

---

## 6. Suitability Analysis

For the college course-fee scenario, the AI agent is suitable for questions that require multiple steps, such as comparing several courses, calculating discounts, and checking a budget. The agent can retrieve the required private course data through tools and then perform calculations using the calculator tool.

The rule-based workflow is suitable for fixed and predictable fee-related operations. Since its steps are predefined, it provides consistent behaviour for the cases that have been programmed.

The plain chatbot is useful for simple conversational questions and general responses. However, when exact course-fee information and calculations are required, relying only on an LLM has limitations.

Therefore, the suitability depends on the type of request. Fixed and predictable questions can be handled using a workflow, while complex questions that require multiple tool calls can be handled using an AI agent. A plain chatbot is useful when the main requirement is natural-language interaction.

---

## 7. Conclusion

A plain chatbot, a rule-based workflow, and an AI agent solve problems in different ways.

A plain chatbot mainly uses an LLM to understand the user's input and generate a response. It is appropriate for general conversational interactions and simple questions.

A rule-based workflow follows predefined steps and conditions without using an LLM for decision-making. It is appropriate for predictable tasks where the possible cases and actions are known in advance.

An AI agent combines an LLM, tools, and a loop. It can understand a task, select appropriate tools, observe the results, and continue with additional actions until the task is completed. This makes it useful for dynamic and multi-step problems.

The main lesson from this project is that the choice of approach should depend on the problem. Simple conversations may use a chatbot, predictable processes may use a rule-based workflow, and multi-step tasks requiring tool usage can use an AI agent.
